# About carousel: GUILDA の出力例

Media of the carousel in the About tab. Every item is drawn by a `plot_*` method of
GUILDA and its graph object (GraphBase). All are regenerated by
`notes/about-anim/make_about_carousel.m` in the guilda repository (R2026a, ffmpeg):

```matlab
addpath("notes/about-anim"); make_about_carousel(OutDir="<docs>/images/about/carousel");
```

Videos: MP4 (H.264, yuv420p, faststart), 1280 x 640 px, 20 frames/s, each with a PNG
poster of the same name. Stills: PNG. The pointer and the blue click rings in 06 to 09
are drawn onto the recorded frames to show where the script clicked; everything else is
the figure as GUILDA draws it. In 09 the result window that Analyze result opens is
recorded as its own figure and drawn over the app, as a window opened over it.

## 01 OPF の LMP

- file: `01-opf-lmp.png`
- poster: (still)
- type: still
- JA: 最適潮流計算（AC OPF）の結果から、各母線の地点別限界価格（LMP）を色で表示しています。送電容量の上限に達したブランチは強調表示され、混雑によって価格が分かれる様子が分かります。
- EN: The locational marginal price (LMP) of each bus of an AC optimal power flow, shown by color. The branch at its capacity limit is highlighted, so you can see how congestion splits the prices.
- code:

```matlab
net = network.IEEE14bus();
net.a_Branch{1}.tab_parameter.operation.Pmax = 1;
res = net.calculate_optimal_powerflow(Method="AC OPF");
G = res.plot_lmp(LabelMode="bus");
```

## 03 地絡事故後のネットワーク図

- file: `03-fault-diagram.mp4`
- poster: `03-fault-diagram.png`
- type: animation (7.3 s)
- JA: 母線 B008 で 1 秒から 1.05 秒まで地絡事故が起きたときの応答を、ネットワーク図で再生しています。ブランチの色は電流、流れる点は有効電力の向きと大きさを表し、右のグラフのカーソルが時刻に追従します（事故中はスロー再生）。
- EN: The response to a fault at bus B008 from 1 s to 1.05 s, played on the network diagram. Branch colors show the current, moving dots the direction and size of the active power, and the cursor of the |V| chart on the right follows the time (slow motion during the fault).
- code:

```matlab
net = network.IEEE14bus();
sc = net.add_scenario("fault", Time=[0, 5]);
sc.add_fault("B008", [1, 1.05]);
res = net.simulate("fault");
[G, G_chart] = res.plot_diagram();
G.play();                        % or drag the playback bar
```

## 04 3 次元のばね質点モデル

- file: `04-spring-model-3d.mp4`
- poster: `04-spring-model-3d.png`
- type: animation (5.6 s)
- JA: 事故後の発電機の動揺を、曲面 z = log|V| 上のばね質点モデルとして動かしています。各ノードは電圧フェーザ、ばねはブランチとリアクタンスで、右のグラフは発電機の角周波数偏差 omega です。
- EN: The swing of the generators after a fault, as a spring-mass picture on the surface z = log|V|. The nodes are voltage phasors, the springs are branches and reactances, and the chart on the right is the frequency deviation omega of the generators.
- code:

```matlab
net = network.IEEE9bus();
sc = net.add_scenario("fault", Time=[0, 5]);
sc.add_fault("B007", [1, 1.05]);
res = net.simulate("fault");
[G, G_chart] = res.plot_spring_model(Dimension=3);
G.export_video("swing.mp4");
```

## 05 連続潮流計算のステップ再生

- file: `05-cpf-steps.mp4`
- poster: `05-cpf-steps.png`

- JA: 連続潮流計算の各ステップを、ネットワーク図と PV 曲線で同時に再生しています。負荷を増やしていくと潮流が変わり、ノーズ（最大負荷点）を越えて下側の解へ進む様子が分かります。

## 06 再生バーとクリックで結果を探る

- file: `06-explore-click.mp4`
- poster: `06-explore-click.png`
- type: interactive (11.0 s)
- JA: 再生バーをドラッグして事故の瞬間に移動し、母線をクリックしています。ElementClickedFcn に書いた数行で、クリックした母線がネットワーク図と右の |V| グラフの両方で選択されます。
- EN: The playback bar is dragged to the moment of the fault and buses are clicked. A few lines in ElementClickedFcn select the clicked bus both in the diagram and in the |V| chart on the right.
- code:

```matlab
[G, G_chart] = res.plot_diagram();   % res of item 03
G.ElementClickedFcn = @(G, d) select_bus(G, G_chart, d);

function select_bus(G, G_chart, d)
    if d.Kind == "bus"
        G.clear_selection();       G.select(d.Tag);
        G_chart.clear_selection(); G_chart.select(d.Tag);
    end
end
```

## 07 コントロールパネルとコマンド

- file: `07-control-panel.mp4`
- poster: `07-control-panel.png`
- type: interactive (11.7 s)
- JA: show_controls で表示したパネルから色・母線の色・3D 表示・母線の高さを切り替え、コマンドでマーカーの大きさを変えています。パネルとプロパティは常に同期し、どちらで変えても図が更新されます。
- EN: The panel of show_controls switches the color, the bus color, the 3D drawing and the bus height, and a command sets the marker size. The panel and the properties stay in step, so a change from either one redraws the figure.
- code:

```matlab
res = network.IEEE39Bus().calculate_powerflow();
G = res.plot_diagram();
G.show_controls();
G.ColorMode = "P";
G.BusColorMode = "V";
G.MarkerSizeMode = "S";
G.Dimension = "3D";
G.BusHeightMode = "V";
```

## 08 固有値をクリックして参加率を見る

- file: `08-eigen-participation.mp4`
- poster: `08-eigen-participation.png`
- type: interactive (11.7 s)
- replaces: the eigenvalue still `images/about/output-eigenvalues.png`
- JA: IEEE 68 母線系統を近似線形化し、左の固有値の図でモードをクリックしています。右のネットワーク図の色が、そのモードへの各母線の参加率に変わります。0.35 Hz の地域間振動モードでは多くの発電機が関わり、1.63 Hz のローカルモードでは母線 B011 の発電機だけが関わります。最後に母線 B014 をクリックすると、下の表にその母線の状態ごとの参加率が出ます。
- EN: The IEEE 68-bus system is linearized and modes are clicked on the eigenvalue map on the left. The diagram on the right is recolored with the participation of each bus in that mode: many generators take part in the inter-area mode of 0.35 Hz, only the generator at bus B011 in the local mode of 1.63 Hz. A click on bus B014 then lists the participation of each of its states in the table below.
- code:

```matlab
net = network.IEEE68bus();
res = net.get_sys();
sct = res.plot_participation();   % click an eigenvalue, then a bus
```

## 09 GUI で編集して解析する

- file: `09-app-gui.mp4`
- poster: `09-app-gui.png`
- type: interactive (14.0 s)
- replaces: the model GUI still `images/about/output-model-gui.png`
- JA: GUILDA のアプリで IEEE 14 母線系統を開き、ネットワーク図で母線 B009 の負荷をクリックして、モデルの GUI で有効電力 P を -0.295 から -0.6 に書き換えています。続けて Power flow のタブで潮流計算を実行し、Analyze result で結果の窓を開いています。操作はすべて MATLAB のコードとして下のログに残り、Export script でスクリプトに書き出せます。
- EN: The GUILDA app opens the IEEE 14-bus system; the load at bus B009 is clicked on the network diagram and its active power P is changed from -0.295 to -0.6 in the model GUI. The Power flow tab then runs the power flow, and Analyze result opens the result window. Every action is kept as MATLAB code in the log below, and Export script writes it out as a script.
- code:

```matlab
h = GUILDA.launch_gui(network.IEEE14bus());
% the log of the session:
net.a_Bus{9}.a_Component{1}.tab_parameter.powerflow.P = -0.6;
[res_pf, flag_pf] = net.calculate_powerflow();
```
