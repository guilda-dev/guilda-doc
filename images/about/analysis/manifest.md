# About carousel: 解析の特長

Media of the carousel of analysis features in the About tab. Each video is a MATLAB
session: the code of the slide is typed into a Command Window, each line is run as it is
and its printed output is shown, then the figures that the code draws are shown as GUILDA
draws them (one at a time, scaled into the frame). Nothing is drawn on the figures and no
code other than the code of the slide changes them, so running the code of a slide gives
the same output and the same figures (the window size aside). Order of the slides:

1. 01 fault simulation
2. 02 Jacobian structure (`make_about_jacobian.m`)
3. 03 PSS added one by one
4. 04 user-written controller (`make_about_custom_controller.m`)
5. 05 OPF formulation (`make_about_opf_formulation.m`)
6. 06 stability-constrained OPF
7. 07 CPF eigenvalues

01, 03, 06 and 07 are regenerated by `notes/about-anim/make_about_analysis.m` in the guilda
repository (R2026a, ffmpeg); 02, 04 and 05 by their own scripts in the same folder (see
the note of each):

```matlab
GUILDA.addpath(); addpath("notes/about-anim"); make_about_analysis(OutDir="<docs>/images/about/analysis");
```

How make_about_analysis runs the code: every line runs with `evalc` in the base workspace, and the
shown output is that text (without the hyperlink markup of `matlab -batch`, which the
desktop shows as plain words). A line `G.animate(...)` runs with `Speed=Inf` and an
`UpdateFcn` that takes one video frame per frame of `animate` (it draws nothing), so the
video at 20 frames/s plays at the speed of the shown call. A `for` loop runs one pass at a
time (its body with the loop variable set), so that each pass is recorded. The progress
dialogs of the analyses (`Progress` "dialog", the default) show nothing in `matlab -batch`.

Videos: MP4 (H.264, yuv420p, faststart), 1280 x 640 px, 20 frames/s, each with a PNG
poster of the same name; the last frames fade into the first, so that the video loops.

## 01 数行のコマンドで事故を模擬する

- file: `01-fault-simulation.mp4`
- poster: `01-fault-simulation.png`
- type: MATLAB session (Command Window, then the figures)
- heading JA: 数行のコマンドで事故を模擬する
- heading EN: A fault simulation in a few commands
- JA: IEEE 14 母線系統で、母線 B008 に 1 秒から 1.05 秒まで地絡事故を起こすシナリオを作り、時間応答シミュレーションを実行します。結果をネットワーク図と発電機の角周波数偏差のグラフで描き、animate で実時間で再生します。
- EN: A scenario with a fault at bus B008 of the IEEE 14-bus system from 1 s to 1.05 s is simulated. The result is drawn as the network diagram with the frequency deviation of the generators and played with animate in real time.
- code:

```matlab
net = network.IEEE14bus();
sc = net.add_scenario("fault", Time=[0, 5]);
sc.add_fault("B008", [1, 1.05]);   % fault at bus B008
res = net.simulate("fault");
G = res.plot_diagram(Trajectory="omega");
G.animate();
```

## 02 ヤコビ行列を要素ごとに取り出す

- file: `02-jacobian-structure.mp4`
- poster: `02-jacobian-structure.png`
- type: MATLAB session (Command Window, then the figures)
- heading JA: ヤコビ行列を要素ごとに取り出す
- heading EN: The Jacobian, taken out element by element
- JA: IEEE 9 母線系統（各発電機に AVR と PSS 付き）を近似線形化し、DAE のヤコビ行列を要素ごとに区切って表示します。次に、発電機 1 とその AVR・PSS の部分だけを取り出して同じように表示します。取り出した部分の状態の行は全体のヤコビ行列と同じ値で（差 0）、残りのすべての要素の部分と足すと全体に戻ります（差は丸め誤差の 7.1e-15）。
- EN: The IEEE 9-bus system (an AVR and a PSS on each generator) is linearized, and the Jacobian of its DAE is drawn with its rows and columns grouped by element. Then the part of generator 1 with its AVR and PSS is taken out and drawn the same way. Its state rows equal those of the whole Jacobian (difference 0), and added to the part of all the other elements it gives the whole Jacobian back (difference 7.1e-15, rounding).
- code:

```matlab
net = network.IEEE9bus(LocalController=true);    % AVR and PSS on each generator
res = net.get_sys();
res.plot_matrix(Matrix="J");                     % the Jacobian of the network
sv_gen = ["B001SG1", "B001SG1CA1", "B001SG1CP2"];   % generator 1, its AVR, PSS
res_g = res.get_contribution(sv_gen);
res_g.plot_matrix(Matrix="J");                   % the part of those three
J = res.get_ss("DAE", Format="struct").A;        % the whole Jacobian
lv_gen = contains(res_g.StateName, "B001SG1");   % the rows of their states
max(abs(res_g.A(lv_gen,:) - J(lv_gen,:)), [], "all")
sv_all = [unique(res.tab_variable.Owner)', "Branch"];   % every element
res_o = res.get_contribution(setdiff(sv_all, sv_gen));   % all the others
max(abs(res_g.A + res_o.A - J), [], "all")
```

- note: made by `notes/about-anim/make_about_jacobian.m` (`make_about_jacobian(OutDir=...)`).
  Every line is typed and run as it is (the printed text is its evalc output: `0` and
  `7.1054e-15`); the two `plot_matrix` lines get `Parent` (the panel below the command
  strip) and the axes toolbars are hidden. Nothing is drawn on the figures by the script.

## 03 制御器を追加して、同じモデルで解析し直す

- file: `03-controller-pss.mp4`
- poster: `03-controller-pss.png`
- type: MATLAB session (Command Window, then the figures)
- heading JA: 制御器を追加して、同じモデルで解析し直す
- heading EN: Add a controller and analyze the same model again
- JA: IEEE 68 母線系統で、AVR だけの状態から発電機に PSS を 1 台ずつ追加します。ループの各回で初期化・近似線形化・事故の時間応答シミュレーションを行い、固有値マップと各発電機の角周波数偏差を描き直します。AVR だけでは 14 個の固有値が不安定ですが、12 台目の追加ですべて安定になります。
- EN: Starting from the IEEE 68-bus system with AVRs only, a PSS is added to one generator after another. Each pass of the loop initializes, linearizes and simulates a fault, and draws the eigenvalue map and the frequency deviation of the generators again. With AVRs only 14 eigenvalues are unstable; from the twelfth PSS on, none is.
- code:

```matlab
net = network.IEEE68bus(LocalController=true);
for i = 1:16                                   % AVRs only: remove the PSSs
    gen = net.a_Bus{i}.a_Component{1};
    gen.remove_local_controller(gen.pss.s_tag);
end
sc = net.add_scenario("fault", Time=[0, 15]);
sc.add_fault("B001", [1, 1.05]);
prm = struct(kpss=25, tWS=10, tn1=0.07, td1=0.02, tn2=0.07, td2=0.02);
fig = figure(Position=[100 100 1280 500]);
for i = 0:16
    if i > 0
        net.a_Bus{i}.a_Component{1}.add_local_controller("pss-PSS1", parameter=prm);
    end
    net.initialize();
    lin = net.get_sys();
    sim = net.simulate("fault");
    clf(fig);
    lin.plot_eigenvalue(Parent=uipanel(fig, Position=[0 0 0.5 1]));
    sim.plot_trajectory(Quantity="omega", Parent=uipanel(fig, Position=[0.5 0 0.5 1]));
    fprintf("%2d PSSs: %2d unstable eigenvalues\n", i, sum(real(lin.get_eigenvalue()) > 1e-6));
end
```

## 04 自作の制御器を、同梱の制御器と同じように使う

- file: `04-custom-controller.mp4`
- poster: `04-custom-controller.png`
- type: MATLAB session (Command Window, then the figures)
- heading JA: 自作の制御器を、同梱の制御器と同じように使う
- heading EN: A controller you write works like a bundled one
- JA: 周波数のずれに比例して機械入力を変えるガバナを LocalController を継承したクラスとして書き、GUILDA のフォルダ内（_GUILDAobject/+controller/+governor/Droop.m）に保存します。GUILDA.update_keymap でキー "gov-droop" を登録すると、add_local_controller で発電機に追加できます。IEEE 9 母線系統で 1 秒に機械入力が 0.1 pu 減ると、既定のガバナ（機械入力一定）では周波数が下がり続け、このガバナを 3 台に付けると約 −0.004 pu で落ち着きます。
- EN: A governor that changes the mechanical power in proportion to the frequency deviation is written as a subclass of LocalController and saved in the GUILDA folder (_GUILDAobject/+controller/+governor/Droop.m). After GUILDA.update_keymap registers its key "gov-droop", add_local_controller adds it to a generator. When the IEEE 9-bus system loses 0.1 pu of mechanical power at 1 s, the frequency keeps falling with the default governors (constant mechanical power) and settles at about −0.004 pu with this governor on the three generators.
- code:

```matlab
% _GUILDAobject/+controller/+governor/Droop.m (in the GUILDA folder)
classdef Droop < LocalController
% Governor with a proportional frequency feedback: Pmech = Pmech_ref - K*omega
    properties (Constant, Hidden)
        key    = "gov-droop"
        s_role = "governor"
    end
    properties (SetAccess=protected, Hidden)
        sv_x    = strings(0,1)             % no state
        sv_u    = ["omega"; "Pmech_ref"]   % omega is read from the generator
        sv_y    = "Pmech"                  % drives Pmech of the generator
        sv_para = "K"
    end
    methods (Access={?Component})
        function obj = Droop(tag, param)
            arguments
                tag (1,1) string
                param.K (1,1) double = 20
            end
            obj@LocalController("CG" + tag);
            obj.a_Parameter{1} = Parameter(obj, "dynamics", struct(K=param.K));
        end
    end
    methods
        function [x, u] = get_equilibrium(obj, V, u_gen)
            x = zeros(0,1);
            u = [0; u_gen(obj.a_Component.sv_u == "Pmech")];
        end
    end
    methods (Static)
        function dx = fcn_dx(t, x, V, u, p, w0), dx = zeros(0,1); end
        function y = fcn_y(t, x, V, u, p, w0), y = u(2) - p(1)*u(1); end
        function M = fcn_Mass(t, x, V, u, p, w0), M = zeros(0,0); end
        function [A, Bv, Bu] = Jacobi_dx(t, x, V, u, p, w0)
            A = zeros(0,0);  Bv = zeros(0,2);  Bu = zeros(0,2);
        end
        function [C, Dv, Du] = Jacobi_Y(t, x, V, u, p, w0)
            C = zeros(1,0);  Dv = zeros(1,2);  Du = [-p(1), 1];
        end
    end
end

% Command Window
GUILDA.update_keymap;   % registers the key of the new class
net = network.IEEE9bus();
sc = net.add_scenario("loss", Time=[0, 30]);
sc.add_input("B002SG1", "Pmech", -0.1, [1, 30]);   % 0.1 pu less Pmech from 1 s
res0 = net.simulate("loss");   % default governors (gov-static)
gens = ["B001SG1", "B002SG1", "B003SG1"];
for s = gens, net.get_element(s).add_local_controller("gov-droop"); end
net.initialize();
res1 = net.simulate("loss");   % gov-droop on the three generators
res0.plot_trajectory(Quantity="omega");
res1.plot_trajectory(Quantity="omega");
```

- note: made by `notes/about-anim/make_about_custom_controller.m`. The script writes the
  class file shown into the GUILDA folder, runs the commands exactly as shown (only
  `GUILDA.update_keymap` prints), records the two figures as GUILDA draws them (side by
  side, each under the command that drew it) and deletes the class file again. The editor
  pane and the Command Window are drawn by the script. GUILDA.keymap finds model classes
  only under the GUILDA folder (GUILDA.dictionary scans GUILDA.pwd), so the class file must
  be saved there.

## 05 最適化問題を確かめてから解く

- file: `05-opf-formulation.mp4`
- poster: `05-opf-formulation.png`
- type: MATLAB session (Command Window, then the figures)
- heading JA: 最適化問題を確かめてから解く
- heading EN: Look at the optimization problem, then solve it
- JA: IEEE 14 母線系統の AC 最適潮流計算の問題を作り、目的関数と制約の一覧をコマンドウィンドウに表示します。目的関数（発電コスト）、発電機の出力の上下限、線路の位相差の制約を一つずつ確かめてから同じ問題を解き、結果の要約と、各機器の出力（P, Q）と母線電圧（大きさと位相）の棒グラフを表示します。
- EN: The AC optimal power flow problem of the IEEE 14-bus system is built and its objective and constraints are listed in the Command Window. The objective (generation cost), the output limits of a generator and the angle-difference limit of a line are shown one by one; then the same problem is solved, its summary is printed and plot_dispatch draws the outputs (P, Q) of the components and the bus voltages (magnitude and angle).
- code:

```matlab
net = network.IEEE14bus();
prob = net.build_opf_problem(Method="AC OPF");
net.solver_OPF.disp_formulation(Method="AC OPF", Problem=prob)
show(prob.Objective.GenCost)
showbounds(prob.Variables.B002SG1)
show(prob.Constraints.VargMax1_EL001)
res = net.calculate_optimal_powerflow(Method="AC OPF", Problem=prob);
res.disp_summary()
res.plot_dispatch();
```

- note: made by `notes/about-anim/make_about_opf_formulation.m` (R2026a, Optimization
  Toolbox, ffmpeg). Every line in the Command Window is a line of the code or the text it
  printed (evalc); the last figure is plot_dispatch as it draws it (only the window sized to
  1280 x 640). The elapsed time in the summary changes from run to run.

## 06 減衰比の下限を満たす最適潮流

- file: `06-stability-opf.mp4`
- poster: `06-stability-opf.png`
- type: MATLAB session (Command Window, then the figures)
- heading JA: 減衰比の下限を満たす最適潮流
- heading EN: An optimal power flow that meets a damping-ratio limit
- JA: IEEE 14 母線系統の AC 最適潮流計算に、最小減衰比 0.048 の制約を加えます。外側の反復で最小減衰比は 0.0447 から 0.0481 に、コストは 8081.5 から 8566.7 に上がります。その解を動作点として初期化して近似線形化すると、電気機械モードの減衰比はすべて 4.8 % 以上です。
- EN: A lower limit of 0.048 on the damping ratio is added to the AC optimal power flow of the IEEE 14-bus system. Over the outer iterations the smallest damping ratio rises from 0.0447 to 0.0481 and the cost from 8081.5 to 8566.7. The network is then initialized at the solution and linearized: every electromechanical mode has a damping ratio of 4.8 % or more.
- code:

```matlab
net = network.IEEE14bus();
res = net.calculate_optimal_powerflow(Method="AC OPF", MinDampingRatio=0.048);
res.sct_stability.tab_iteration(:, ["Iteration", "Cost", "MinDampingRatio"])
res.plot_dispatch();
net.initialize(Method="OPF", MinDampingRatio=0.048);   % the solution as the operating point
lin = net.get_sys();
lin.disp_mode(MinFrequency=0.1)
lin.plot_eigenvalue();
```

## 07 負荷を増やしながら小信号安定性を調べる

- file: `07-cpf-eigenvalue.mp4`
- poster: `07-cpf-eigenvalue.png`
- type: MATLAB session (Command Window, then the figures)
- heading JA: 負荷を増やしながら小信号安定性を調べる
- heading EN: Small-signal stability while the load grows
- JA: IEEE 14 母線系統で母線 B009 と B014 の負荷を増やす連続潮流計算を行い、ステップ 1〜140（λ = 4.15 まで）の動作点で近似線形化します。固有値マップを PV 曲線と連動させて再生すると、ノーズ（λ = 5.21）より手前のステップ 104（λ = 3.11）で実固有値が正になり、赤で示されます。このモデルの界磁電圧と機械入力は一定です。
- EN: A continuation power flow of the IEEE 14-bus system increases the loads at buses B009 and B014, and the network is linearized at steps 1 to 140 (up to λ = 4.15). Played linked with the PV curve, a real eigenvalue turns positive (red) at step 104 (λ = 3.11), before the nose at λ = 5.21. The field voltage and the mechanical input of this model are constant.
- code:

```matlab
net = network.IEEE14bus();
net.initialize();
cpf = net.calculate_continuation_powerflow(LoadBus=["B009", "B014"]);
cpf.r_lambdaMax
lin = net.get_sys({cpf, 1:140});                 % linearize at steps 1 to 140
fig = figure(Position=[100 100 1280 640]);
G = lin.plot_eigenvalue(Parent=uipanel(fig, Position=[0 0 0.5 1]));
G.link(cpf.plot_pvcurve(Parent=uipanel(fig, Position=[0.5 0 0.5 1])));
G.animate(TimeStep=1, Speed=20);
```

- note: steps 1 to 140 only: near the nose the algebraic part of the model becomes
  singular (around step 174) and a real eigenvalue runs off to +350 1/s and comes back
  from -6000 1/s, so a map of every step up to the nose (`1:cpf.r_noseStep`) has a real
  axis down to -6000 and shows nothing. plot_eigenvalue_path is left out: for these
  sections it labels its x axis "t [s]" (GUILDA takes the step numbers in rv_t for times),
  and the eigenvalue map titles each section "t = k" for the same reason.
